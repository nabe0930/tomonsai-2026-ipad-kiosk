# 稲門祭2026 iPadセルフ受付

2026年10月12日更新・受付アプリv19。

会場のiPadで使う予約・支払案内用Webアプリです。画面タイトルは2026年最終企画書の「学生注目！透明標本の封入体験するよ！」に合わせ、タイトル周りのサブタイトルは表示しません。左上には[校友会の2026年公式ロゴ](https://www.wasedaalumni.jp/alumni/wp-content/uploads/2026/03/side_logo_2026.jpg)を、元のJPEGを加工せず同梱して表示します。オフラインでも表示します。v19では来場者の予約はPayPayのみです。個人Myコードで送金するときは、送金メッセージに画面の受付番号（例：001）を入力してもらいます。現金希望者は事前予約せず、希望する回の開始時刻に集合し、その時点で人数分の空席があればスタッフが現金受付を行います。「PayPay登録」で個人Myコード（送金）または加盟店の決済QRを選び、手元の画像へ差し替えられます。参加費は1人1,000円、体験は20分、各回の参加上限は20名で、5回分の合計は100名です。日付と現在時刻による受付制限はなく、運営者が受付を開き、定員に空きがあればいつでも操作できます。枠時刻は体験予定の表示として残ります。来場者画面のイラストはありません。記録はこの端末のブラウザ内に保存され、他端末とは同期しません。

- 公開URL: https://nabe0930.github.io/tomonsai-2026-ipad-kiosk/
- 来場者画面には「事前予約は、PayPayでの事前支払いのみです」「現金払いは、各回に空席がある場合に限ります」を大きく常時表示します。
- 来場者: 空き枠の「予約する」から体験人数を選び、注意事項を確認して「予約番号を発行」で未払いのPayPay予約を作成します。支払方法はPayPayのみで、現金の選択や予約後の現金への切替はありません。番号発行後にQR・人数分の合計額と、個人Myコードの場合は送金メッセージに入れる受付番号を表示します。運営者がPayPayを停止した場合、新しい来場者予約はできません。番号発行と同時に残席が減ります。予約やQR表示では入金済みになりません。
- 定員: 各回20名です。ある回が満席でも、他の回に空きがあれば予約できます。5回すべての合計定員は100名です。旧版のJSONやリセット控えを復元するときも、定員を各20名に揃えて予約・番号・入金記録を保持します。
- 人数: 1回の予約は最大4名です。予約画面には1・2・3・4名の選択肢を常に表示し、残席を超える人数は選べません。残席に応じた説明を表示します。空きが4名ある枠なら4名を選べます。
- 付き添い: 「付き添いは2名まで」の注意書きで案内します。付き添い人数の選択欄はなく、新しい記録へ保存しません。定員判定は体験参加者数だけで行い、在室上限の設定欄・受付制限はありません。
- 体験時の注意: 体験では基本的に安全な物質を使用していますが、標本や液体などを口に入れないようお願いいたします。液体をこぼした場合などは、スタッフにお知らせください。体験中は、スタッフの説明や指示に従ってください。
- 予約番号: 新しい予約には `001`、`002`、`003` のように予約1件ごとの連番を発行します。人数ごとの番号ではありません。取消・完了済みの番号も再利用しません。旧版で発行した英字を含む番号や入金記録は、更新・JSON復元で変更しません。
- PayPay: 付属のMyコードを予約後に表示します。個人Myコードは送金で、加盟店決済とは区別します。運営者自身のPayPay受取履歴で相手・時刻・人数分の金額・受け取り完了を確認し、同じ送金元のメッセージ／チャットの受付番号と照合した後、「PayPayを確認」で記録します。加盟店の決済QRを登録した予約は、PayPay for Businessで店舗・時刻・金額・取引完了を照合します。新しい入金記録は個人送金の `paypay-personal` と加盟店の手動確認の `paypay-manual` を区別します。同じ確認済み取引を別の予約へ使い回しません。アプリによる送金・決済実行、自動照合、来場者の自己申告による入金確定はありません。以前の版の取引番号・確認待ち番号・返金処理は保持します。
- 現金: 事前予約なしで、希望する回の開始時刻に集合してもらいます。スタッフが選択した回の開始・本人の来場・人数分の空席を確認し、人数×1,000円を実際に受け取った後、「現金受付」で支払済み番号を登録します。席の確保や参加は保証しません。新しいPayPay予約は現金で入金確認できません。旧版の現金予約・入金記録は保持し、従来の「現金を確認」で処理できます。入金・安全説明を確認してから着席を記録します。日時による自動制限は追加せず、当該回の開始はスタッフが確認します。
- 未払いの予約も席を占有します。不要な予約は運営者が手動で取り消します。日付が変わっても自動取消や台帳の初期化は行いません。
- 新しい端末での本番初期状態は受付停止中です。運営者PINを設定してから受付を開始します。参加費は1人1,000円・体験20分で固定、5枠は各20名で固定です。既存の予約・入金記録・番号を保持したまま、旧版の枠定員も各20名へ更新します。在室上限の設定は不要です。別端末で同じ公開URLを開いて作った予約は、会場iPadに同期されません。公開URLを遠隔予約の入口として案内しないでください。
- CSV控えは付き添い人数・小学生以下の列を出しません。JSONバックアップは旧版の記録にあるそれらの項目を履歴として保持します。
- この更新はアプリに対するものです。公開版の更新とiPad実機での更新確認は別です。iPadのv19表示・実機動作・ホーム画面への追加完了・実機のQR登録状態は未確認です。実機の確認ではアプリの削除やサイトデータの消去を行わず、既存の予約を保持します。

## 運営者画面

- 「受付」「現金受付」「設定」の3つから操作を選びます。上部に固定された「受付画面に戻る」で来場者画面へ戻れます。
- 「受付」には参加者数・残り人数・未払い件数・各枠の残席と、予約番号ごとのカードを表示します。「PayPayを確認」「入場を確認」「完了にする」など、状態に応じた操作を選べます。旧版の現金予約には「現金を確認」も表示します。入金確認前は入場を記録できません。完了・取消の記録は折りたたんでいます。
- 「現金受付」（画面見出し「開始回の空席で現金受付」）は、希望回の開始時刻に来場した現金希望者を、人数分の空席がある場合だけ受け付ける画面です。スタッフが選択回の開始・本人の来場・現金の受領を確認してから支払済み番号を登録します。旧版の現金予約への入金記録は「受付」から行います。
- 「設定」の「時間・定員」「控えの保存・復元」「PayPay登録」は必要なときだけ開きます。「控えを保存」はJSON、「一覧を保存（CSV）」は一覧表の書き出しです。「控えから復元」は現在の記録をファイルの内容へ置き換えます。

## 予約をリセットする

- 「受付」の「予約をリセット」は、現在の台帳をこの端末内の控えへ保存して読み返せたことを確認した後、予約記録を0件にして受付を停止します。設定・PIN・QR画像は残ります。控えの保存・確認に失敗した場合はリセットしません。
- 練習モードでは次の番号を001に戻します。本番では連番を継続し、発行済み番号を再利用しません。リセット後に予約を受け付けるには「受付を開始」を押します。
- 控えがあると「元に戻す」を使えます。現在の予約を控えに保存し、前の台帳の予約・設定へ切り替えて受付を停止します。現在のPIN・QR画像は保持し、番号が重複しないよう連番を調整します。リセット後に発行した予約も控えに残り、再度「元に戻す」で切り替えられます。控えは直前の1世代です。
- 「設定」→「控えの保存・復元」→「前の予約の控えを保存」で、この控えをJSONとして書き出せます。端末内の控えだけでなく、別の保存先にも保存してください。
- リセット・「元に戻す」は台帳の切替で、実際の支払いや返金を行いません。

## いつでも練習する

- 練習URL: https://nabe0930.github.io/tomonsai-2026-ipad-kiosk/?mode=test&v=19
- 本番の運営者画面からも練習モードを開けます。画面上部の「練習」の表示を確認してください。実際のお金を受け取る必要はありません。
- 来場者画面で「予約する」→ 人数などを選ぶ → 注意事項を確認 →「予約番号を発行」と操作します。運営者画面に入らず予約を作れます。この時点では未払いで、受領確認は不要です。
- 支払いの記録も試す場合は「運営者用」を開き、練習専用PIN **000000** で入ります。新しい予約番号のPayPay入金確認と、「現金受付」からの当日現金受付を練習として操作します。練習の予約後には専用QRを表示します。このQRは練習ページを開くためのもので、実際のPayPay決済にはつながりません。実際の金銭の受け渡しは不要です。
- 新しい練習台帳は受付開始済みで始まります。参加者数だけで定員を判定し、在室上限の入力は不要です。「予約をリセット」で練習記録だけを0件にし、設定・PIN・QR画像を残して受付を停止します。「受付を開始」を押すと001から新しく発行できます。本番の記録は変わりません。
- 練習の受付記録・PIN・差し替えQR画像は本番と別の端末内保存領域を使います。本番の記録とPINは変わりません。本番へ戻るリンクから切り替えてください。管理画面で参照できる個人Myコードの初期画像は共通ですが、練習の来場者画面には決済用ではない専用QRを使います。
- 練習JSONは `purpose: test` を付け、練習と本番の間で復元できないようにしています。書き出し名には書き出した日の年月日を使い、練習のファイルには「練習」を付けます。
- 本番の記録は日付が変わっても自動で消えません。開催日や現在時刻を変えてテストする必要はありません。

## QR画像の保存とPayPayの確認

付属画像 `payment-qr.png` は2026年10月12日に提供された個人のMyコードをQR部分だけ切り取ったものです。本番の予約後に表示します。有効期限は**2026年10月26日10:08**です。請求金額は設定されていないため、来場者のスマホで人数×1,000円の合計額を入力します。v19でもこの付属QRを使用し、独自に登録したQR・PIN・既存の予約・入金記録・受付開始／停止の状態は保持します。

1. 会場iPadのホーム画面アプリを開き、「運営者用」でPINを入力して「設定」→「PayPay登録」を開きます。
2. 「QRの種類」で「個人のMyコード（送金）」または「加盟店の決済QR」を選びます。
3. 「差し替えるQR画像」でPNG/JPEG画像（2MiB以下）を選びます。選択は仮置きで、この時点では保存しません。個人Myコードでは付属QRまたは既存画像、加盟店では登録済み加盟店QRを再利用する場合、画像を選び直す必要はありません。
4. 「QRを登録してPayPayを使う」を押します。画像と種類の保存、PayPayの有効化をまとめて行います。来場者の予約画面がPayPayのみになり、予約後にQR・人数分の合計額と、個人Myコードの場合は送金メッセージに入れる受付番号が表示されることを確認します。

アプリは画像のQR内容・有効期限・決済可否そのものを認証しません。種類不明の旧画像は個人送金として引き継ぎ、加盟店QRとして再利用しません。旧版で加盟店QRと利用準備を登録済みの場合は、その種類を保持します。それ以外の旧設定は更新時に一度、個人Myコード・PayPay有効へ移行します。以後「PayPayを停止」で止めた状態は保持します。受付開始・停止の状態、予約・番号・PIN・入金記録は変えません。

「PayPayを停止」はQRと予約記録を残してPayPay案内と来場者の新しい予約を停止します。現金への予約切替は行いません。現金希望者には希望回の開始時刻に集合し、空席があれば参加できることを案内します。「登録QRを削除」は端末内の登録画像を削除し、PayPay案内も停止します。予約・番号・PIN・入金記録は消しません。

差し替えQRは会場iPad内だけに保存され、GitHubへ送信されません。JSON/CSV控えに画像は含まれず、別端末へ同期されないため、端末を替えた場合は再登録が必要です。練習と本番の登録先も別です。

個人Myコードは加盟店決済ではなく送金です。PayPay公式は個人送金での商品代金受領を禁止しています。QRを表示できることは、この利用が公式に認められたことを意味しません。加盟店の店頭QRは公開配信に追加せず、会場端末内に登録します。[個人送金での商品代金受領](https://paypay.ne.jp/help-merchant/b0861/)・[店頭QRのオンライン掲載](https://paypay.ne.jp/help-merchant/b0518/)

付属Myコードを読み取ったら、スマホで表示する人数×1,000円の合計額と、送金メッセージに画面の受付番号（例：001）を入力します。送金できず不要となった予約は、スタッフが受取履歴で入金がないことを確認して取り消します。現金で参加する場合は、希望回の開始時刻に来場し、その時点の空席で受け付けます。PayPayの結果が不明なまま現金も受け取らず、先に受取履歴を確認します。API秘密情報は公開配信ファイルに含めません。
