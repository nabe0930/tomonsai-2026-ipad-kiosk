# 稲門祭2026 iPadセルフ受付

会場のiPadで使う予約用Webアプリです。参加費は1人1,000円、体験は20分、参加上限は20名です。日付と現在時刻による受付制限はなく、運営者が受付を開き、定員に空きがあればいつでも操作できます。枠時刻は体験予定の表示として残ります。来場者画面のイラストはありません。記録はこの端末のブラウザ内に保存され、他端末とは同期しません。

- 公開URL: https://nabe0930.github.io/tomonsai-2026-ipad-kiosk/
- 来場者: 空き枠の「予約する」から体験する人数を選び、注意事項を確認して「予約番号を発行」で未払いの予約番号を作成します。番号発行と同時に残席が減ります。支払い確認や入金記録はこの操作に含まれません。
- 人数: 1回の予約は最大4名です。予約画面には1・2・3・4名の選択肢を常に表示し、残席を超える人数は選べません。残席に応じた説明を表示します。空きが4名ある枠なら4名を選べます。
- 付き添い: 「付き添いは2名まで」の注意書きで案内します。付き添い人数の選択欄はなく、新しい記録へ保存しません。定員判定は体験参加者数だけで行い、在室上限の設定欄・受付制限はありません。
- 体験時の注意: 体験では基本的に安全な物質を使用していますが、標本や液体などを口に入れないようお願いいたします。液体をこぼした場合などは、スタッフにお知らせください。体験中は、スタッフの説明や指示に従ってください。
- 予約番号: 新しい予約には `001`、`002`、`003` のように予約1件ごとの連番を発行します。人数ごとの番号ではありません。取消・完了済みの番号も再利用しません。旧版で発行した英字を含む番号や入金記録は、更新・JSON復元で変更しません。
- 現金: 予約番号をスタッフへ伝え、支払います。運営者が実際の受領を確認して管理画面に入金を記録し、支払い・安全説明を対面で確認して着席を記録します。運営者による支払済み番号の直接登録も、実際の受領後だけ行います。
- PayPay: 初期状態では無効。OFFでも予約できます。将来ONにしても、来場者画面で行う操作は予約番号の発行のみです。決済の送信・自動入金判定・来場者画面へのQR表示は行いません。以前の版で発行したPayPay支払い待ち番号の管理処理と、運営者用QR画像の端末内保存は残ります。
- 未払いの予約も席を占有します。不要な予約は運営者が手動で取り消します。日付が変わっても自動取消や台帳の初期化は行いません。
- 新しい端末での本番初期状態は受付停止中です。運営者PINを設定してから受付を開始します。参加費は1人1,000円・体験20分で固定、枠の初期配分は5枠×各4名です。在室上限の設定は不要です。別端末で同じ公開URLを開いて作った予約は、会場iPadに同期されません。公開URLを遠隔予約の入口として案内しないでください。
- CSV控えは付き添い人数・小学生以下の列を出しません。JSONバックアップは旧版の記録にあるそれらの項目を履歴として保持します。
- iPadのホーム画面追加は、構成プロファイルのiPad本体での承認待ちです。インストール完了や更新版の実機動作は未確認です。

## いつでも練習する

- 練習URL: https://nabe0930.github.io/tomonsai-2026-ipad-kiosk/?mode=test&v=10
- 本番の運営者画面からも練習モードを開けます。画面上部の「練習」の表示を確認してください。実際のお金を受け取る必要はありません。
- 来場者画面で「予約する」→ 人数などを選ぶ → 注意事項を確認 →「予約番号を発行」と操作します。運営者画面に入らず予約を作れます。この時点では未払いで、受領確認は不要です。
- 支払いの記録も試す場合は「運営者用」を開き、練習専用PIN **000000** で入ります。予約番号の現金入金確認を練習として操作します。実際の金銭の受け渡しは不要です。
- 練習は受付開始済みで始まります。参加者数だけで定員を判定し、在室上限の入力は不要です。「練習の受付記録をリセット」で練習記録だけを初期化し、新しく連番の発行を試せます。本番の記録は消えません。
- 練習の受付記録・PIN・QR画像は本番と別の端末内保存領域を使います。本番の記録とPINは変わりません。本番へ戻るリンクから切り替えてください。
- 練習JSONは `purpose: test` を付け、練習と本番の間で復元できないようにしています。書き出し名には書き出した日の年月日を使い、練習のファイルには「練習」を付けます。
- 本番の記録は日付が変わっても自動で消えません。開催日や現在時刻を変えてテストする必要はありません。

## 将来のPayPay

将来、運営者は会場のiPadに追加したホーム画面アプリの管理画面から、公式店舗QRのPNG/JPEG画像（2MiB以下）を自分で選べます。画像はそのiPad内だけに保存され、管理画面でのみプレビューできます。来場者画面には表示されず、PayPay受付を自動で有効にしません。JSON/CSV控えにも画像は含まれず、別端末へ同期されません。端末を替えた場合は再登録が必要です。

このアプリはPayPayへ決済を送信せず、自動で入金を判定しません。加盟店QRの画像やAPI秘密情報をGitHub・公開サイトには置きません。実際の支払いには会場で掲示する公式紙QRかPayPay for BusinessアプリのQR画面を使います。運用手順は別途配布した導入ガイドを参照してください。
