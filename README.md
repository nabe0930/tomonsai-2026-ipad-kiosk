# 稲門祭2026 iPadセルフ受付

会場のiPadで使う予約・支払案内用Webアプリです。画面タイトルは2026年最終企画書の「学生注目！透明標本の封入体験するよ！」に合わせ、タイトル周りのサブタイトルは表示しません。v14は加盟店QRと利用準備が整った後にPayPayを基本とし、利用できない場合は現金へ切り替えます。現在提供されている個人のMyコードだけでは本番のPayPay受付は有効にならず、現金で受け付けます。参加費は1人1,000円、体験は20分、各回の参加上限は20名で、5回分の合計は100名です。日付と現在時刻による受付制限はなく、運営者が受付を開き、定員に空きがあればいつでも操作できます。枠時刻は体験予定の表示として残ります。来場者画面のイラストはありません。記録はこの端末のブラウザ内に保存され、他端末とは同期しません。

- 公開URL: https://nabe0930.github.io/tomonsai-2026-ipad-kiosk/
- 来場者: 空き枠の「予約する」から体験する人数と支払方法を選び、注意事項を確認して「予約番号を発行」で未払いの予約番号を作成します。本番のPayPay準備が整っている場合はPayPayが初期選択で、番号発行後にQRと人数分の合計額を表示します。準備が整っていない場合は現金を案内します。番号発行と同時に残席が減ります。予約やQR表示では入金済みになりません。
- 定員: 各回20名です。ある回が満席でも、他の回に空きがあれば予約できます。5回すべての合計定員は100名です。旧版のJSONやリセット控えを復元するときも、定員を各20名に揃えて予約・番号・入金記録を保持します。
- 人数: 1回の予約は最大4名です。予約画面には1・2・3・4名の選択肢を常に表示し、残席を超える人数は選べません。残席に応じた説明を表示します。空きが4名ある枠なら4名を選べます。
- 付き添い: 「付き添いは2名まで」の注意書きで案内します。付き添い人数の選択欄はなく、新しい記録へ保存しません。定員判定は体験参加者数だけで行い、在室上限の設定欄・受付制限はありません。
- 体験時の注意: 体験では基本的に安全な物質を使用していますが、標本や液体などを口に入れないようお願いいたします。液体をこぼした場合などは、スタッフにお知らせください。体験中は、スタッフの説明や指示に従ってください。
- 予約番号: 新しい予約には `001`、`002`、`003` のように予約1件ごとの連番を発行します。人数ごとの番号ではありません。取消・完了済みの番号も再利用しません。旧版で発行した英字を含む番号や入金記録は、更新・JSON復元で変更しません。
- PayPay: 本番では端末内に加盟店QRを登録し、加盟店契約・会場利用の承認・公式QRの会場掲示・スタッフ用PayPay for Businessでの取引確認の4条件を確認して準備完了を保存すると利用できます。来場者が自分のスマホで予約後の加盟店QRを読み取り、人数分の合計額を支払います。運営者はPayPay for Businessで店舗・時刻・金額と取引完了を照合してから、番号の「PayPayを確認」で入金を記録します。新しい記録は手動確認を表す `paypay-manual` です。決済API・自動照合・来場者の自己申告による入金確定はありません。以前の版のPayPay取引番号・確認待ち番号・返金処理は保持します。
- 現金: PayPayを利用できない場合は現金を選び、同じ予約番号をスタッフへ伝えて支払います。運営者が実際の受領を確認し、番号の「現金を確認」で入金を記録します。現金へ切り替えるために予約をもう一度作る必要はありません。運営者による支払済み番号の直接登録も、実際の受領後だけ行います。入金・安全説明を確認してから着席を記録します。
- 未払いの予約も席を占有します。不要な予約は運営者が手動で取り消します。日付が変わっても自動取消や台帳の初期化は行いません。
- 新しい端末での本番初期状態は受付停止中です。運営者PINを設定してから受付を開始します。参加費は1人1,000円・体験20分で固定、5枠は各20名で固定です。既存の予約・入金記録・番号を保持したまま、旧版の枠定員も各20名へ更新します。在室上限の設定は不要です。別端末で同じ公開URLを開いて作った予約は、会場iPadに同期されません。公開URLを遠隔予約の入口として案内しないでください。
- CSV控えは付き添い人数・小学生以下の列を出しません。JSONバックアップは旧版の記録にあるそれらの項目を履歴として保持します。
- この更新はアプリに対するものです。公開版の更新とiPad実機での更新確認は別です。iPadのv14表示・実機動作・ホーム画面への追加完了は未確認です。実機の確認ではアプリの削除やサイトデータの消去を行わず、既存の予約を保持します。

## 運営者画面

- 「受付」「現金受付」「設定」の3つから操作を選びます。上部に固定された「受付画面に戻る」で来場者画面へ戻れます。
- 「受付」には参加者数・残り人数・未払い件数・各枠の残席と、予約番号ごとのカードを表示します。「PayPayを確認」「現金を確認」「入場を確認」「完了にする」など、状態に応じた操作を選べます。入金確認前は入場を記録できません。完了・取消の記録は折りたたんでいます。
- 「現金受付」は、スタッフが実際に現金を受け取った後で支払済み番号を直接登録する画面です。発行済みの未払い番号への入金記録は「受付」から行います。
- 「設定」の「時間・定員」「控えの保存・復元」「PayPay・QR」は必要なときだけ開きます。「控えを保存」はJSON、「一覧を保存（CSV）」は一覧表の書き出しです。「控えから復元」は現在の記録をファイルの内容へ置き換えます。

## 予約をリセットする

- 「受付」の「予約をリセット」は、現在の台帳をこの端末内の控えへ保存して読み返せたことを確認した後、予約記録を0件にして受付を停止します。設定・PIN・QR画像は残ります。控えの保存・確認に失敗した場合はリセットしません。
- 練習モードでは次の番号を001に戻します。本番では連番を継続し、発行済み番号を再利用しません。リセット後に予約を受け付けるには「受付を開始」を押します。
- 控えがあると「元に戻す」を使えます。現在の予約を控えに保存し、前の台帳の予約・設定へ切り替えて受付を停止します。現在のPIN・QR画像は保持し、番号が重複しないよう連番を調整します。リセット後に発行した予約も控えに残り、再度「元に戻す」で切り替えられます。控えは直前の1世代です。
- 「設定」→「控えの保存・復元」→「前の予約の控えを保存」で、この控えをJSONとして書き出せます。端末内の控えだけでなく、別の保存先にも保存してください。
- リセット・「元に戻す」は台帳の切替で、実際の支払いや返金を行いません。

## いつでも練習する

- 練習URL: https://nabe0930.github.io/tomonsai-2026-ipad-kiosk/?mode=test&v=14
- 本番の運営者画面からも練習モードを開けます。画面上部の「練習」の表示を確認してください。実際のお金を受け取る必要はありません。
- 来場者画面で「予約する」→ 人数などを選ぶ → 注意事項を確認 →「予約番号を発行」と操作します。運営者画面に入らず予約を作れます。この時点では未払いで、受領確認は不要です。
- 支払いの記録も試す場合は「運営者用」を開き、練習専用PIN **000000** で入ります。予約番号のPayPay・現金の入金確認を練習として操作します。練習の予約後には専用QRを表示します。このQRは練習ページを開くためのもので、実際のPayPay決済にはつながりません。実際の金銭の受け渡しは不要です。
- 新しい練習台帳は受付開始済みで始まります。参加者数だけで定員を判定し、在室上限の入力は不要です。「予約をリセット」で練習記録だけを0件にし、設定・PIN・QR画像を残して受付を停止します。「受付を開始」を押すと001から新しく発行できます。本番の記録は変わりません。
- 練習の受付記録・PIN・差し替えQR画像は本番と別の端末内保存領域を使います。本番の記録とPINは変わりません。本番へ戻るリンクから切り替えてください。管理画面で参照できる個人Myコードの初期画像は共通ですが、練習の来場者画面には決済用ではない専用QRを使います。
- 練習JSONは `purpose: test` を付け、練習と本番の間で復元できないようにしています。書き出し名には書き出した日の年月日を使い、練習のファイルには「練習」を付けます。
- 本番の記録は日付が変わっても自動で消えません。開催日や現在時刻を変えてテストする必要はありません。

## QR画像の保存とPayPayの確認

利用者が提供した画像からQRコード部分だけを切り取り、参照用の初期画像 `payment-qr.png` として組み込みました。この画像は公開配信ファイルに含まれ、管理画面でのみ参照できます。本番の来場者には表示しません。画像は個人の「Myコード」で、リクエスト金額は1,000円、有効期限は**2026年10月17日14:52**です。開催予定の10月18日には失効します。この画像を料金用の加盟店QRとして扱いません。

運営者は会場のiPadに追加したホーム画面アプリで「設定」→「PayPay・QR」を開き、差し替え用のPNG/JPEG画像（2MiB以下）とQRの種類を選べます。初期選択は参照用で、加盟店QRを登録するときだけ加盟店用の種類を選びます。旧版から引き継いだ種類不明の差し替え画像も、本番の加盟店QRとしては扱いません。差し替え画像と種類はその端末内だけに保存され、GitHubには送信されません。JSON/CSV控えに画像は含まれず、別端末へ同期されないため、端末を替えた場合は再登録が必要です。「差し替え画像を削除」を押すと、管理画面の初期画像へ戻り、本番のPayPay案内は利用できなくなります。アプリは画像自体の加盟店資格・有効期限・決済可否を認証しません。

このアプリはPayPayへ決済を送信せず、自動で入金を判定しません。API秘密情報は公開配信ファイルに含めません。組み込み画像は加盟店の決済QRとして認証した画像ではありません。PayPay公式は個人送金での商品代金受領を禁止しています。料金の受領に使う加盟店の決済手段と会場での利用条件は別途確認し、公式店舗QRを用意してください。加盟店の店頭QRは公開配信に追加せず、会場端末内の差し替え登録を使います。[個人送金での商品代金受領](https://paypay.ne.jp/help-merchant/b0861/)・[店頭QRのオンライン掲載](https://paypay.ne.jp/help-merchant/b0518/)

本番のPayPay案内は、端末内の加盟店QR・4つの準備条件・準備完了の設定がすべて揃った場合だけ表示します。アプリの更新だけでこれらの設定を準備完了へ書き換えません。画像や設定欄の登録だけで加盟店審査・会場利用の承認・支払いの成立をアプリが認証するものではありません。
